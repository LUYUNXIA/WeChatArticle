# 文章审核机制

## 默认执行与边界

本账号每次选题、规划、写稿、修改稿件均自动审核，用户无需再说“审核一下”。目标是让读者相信继续阅读会获得新的理解、真实进展或可用判断；不承诺读完率、爆款或涨粉。审核是编辑判断，效果须由真实后台数据验证。

先读取最新定稿、最近相关文章和本次素材。把作者明确提供的事实、已有旧稿中的未核细节、编辑推断分开；旧稿出现过不等于事实已获确认。作者经历不可用“常见场景”补写成第一人称。

## 写前：值得独立成篇吗

用具体内容回答：谁为什么点进来；她带着什么问题；本篇提供了上篇没有的新材料或新判断；结尾能兑现什么。连载还要摘录上篇的明确预告，说明本篇如何兑现，同时让首次阅读的人也能理解。

删除新标题后，若正文与上一篇仍在反复说明同一结论，应缩小到一个能展开的事件，或合并、延期，不因排期到了硬凑文章。选题评分沿用主技能标准，不替代本关。

## 写中：阅读动力来自推进

- 开头在约150字内交代具体处境、在意的事和仍待解答的问题；不把全部结论提前讲完，也不故意藏起理解所需的信息。
- 逐段注明其贡献：新事实、尝试与结果、认知修正、可验证判断或必要情绪停顿。删掉不影响理解和情绪推进的段落；连续只换词重复委屈或道理的段落须合并或重写。
- 每个主要部分说明“读者此刻知道了什么，还想知道什么，下一部分用什么回答”。没有统一字数间隔、小标题数量或强制反转；安静叙述也须有细节与理解的进展。
- 写出选择的理由与代价，而不只写“我难过、我醒悟”。判断要有事件或行为支撑，避免把简短回复直接判定为不爱或长期敷衍。
- 找出最可能退出阅读的三处（短文按实际数量），引用原句或段落位置，解释原因并直接修改；不能仅写“增强共鸣、加强张力”。
- 结尾回答本篇核心问题，留下有依据的观察或行动。下一篇预告只承诺已有素材支持的具体问题，不截断本篇答案，不使用空泛“更精彩在后面”。连载不必每篇重复征稿和改编说明。

## 交付判定

以下六项分别评为“通过 / 待修改 / 素材不足”，每项附段落证据及理由：

| 项目 | 通过条件 |
|---|---|
| 点击与开头 | 标题承诺明确，开头有与目标读者相关的具体问题 |
| 独立增量 | 能列出区别于近期文章的新材料或有证据的新理解 |
| 推进与阅读动力 | 各主要部分推进问题，重复和退出点已处理 |
| 人物与可信度 | 选择、犹豫、变化有素材支持，无杜撰事实或心理定罪 |
| 本篇兑现 | 结尾实质回答开头，读者得到具体判断或理解 |
| 继续阅读的信任 | 连载承接上篇承诺；如有下篇预告，具体且有素材依据 |

虚构作者经历、用旧内容包装成新故事、标题或上篇预告未兑现，均不能判为可发布。不得用总分抵消单项缺陷；不得用主观评分冒充读者测试。

先自行修正再复审，最多两轮集中修改；仍不通过则如实交付待核稿或规划及未解决原因，不无限润色，不降低门槛。只有六项通过且无事实缺口，才可标记“编辑审核通过”；这不等于实际传播效果已验证，也不授权自动发布。

审核记录只保留当前版本：日期、审核阶段、六项结论与证据、相较上篇的增量、主要删改、待补素材、最终状态。规划阶段明确哪些只是拟写目标，不给不存在的正文打通过。交付时简述状态和主要变化，不让用户再发起一次审核。
