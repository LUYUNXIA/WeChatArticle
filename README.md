# 向阳小人间 · 微信公众号内容运营项目

本仓库用于管理微信公众号「向阳小人间」的内容策划、文章生产、发布排期、文风规范和运营复盘。

账号当前核心合集为「向内生长」，关注普通人在婚姻、育儿和自我关系中的真实消耗与成长。内容不教读者赢过别人，而是帮助读者看见自己、安顿自己，并以更稳定的方式理解伴侣、保护孩子。

> 人生最好的成长，是向内生长，从容面对生活，认真活成自己喜欢的样子。

## 项目目标

- 面向 28—45 岁、关注自我成长、婚姻关系和孩子内心成长的女性读者；
- 以约 60% 的个人心态、婚姻内耗、自我和解内容，搭配约 40% 的育儿三观、孩子内心成长内容；
- 前 12 周形成至少 25 篇原创内容资产，并找到两个稳定的高反馈题型；
- 建立「选题—写作—发布—数据记录—复盘—调整」的内容闭环；
- 保持清醒、克制、温暖的表达：有判断，但不审判。

## 内容生产流程

1. **确定选题**：从排期、读者留言和历史数据中选择候选题，按读者痛感、具体程度、转发理由、搜索寿命和定位匹配度评分；总分低于 18 分不写。
2. **搭建结构**：明确一个核心读者、一个核心冲突、一个核心判断和读者看完后能带走的内容。
3. **完成初稿**：建议 1600—2400 字，以自然完整为准；前 150 字进入具体场景，每 300—500 字提供新的判断、例子或转折。
4. **编辑校验**：依照文风手册删除套话、重复、虚构细节和机械排比，检查标题与正文是否兑现同一件事。
5. **发布包装**：准备标题备选、60—90 字摘要、正文配图、留言问题和公众号封面。
6. **记录数据**：在发布后 T+1、T+3、T+7 更新数据看板，记录阅读、分享、收藏、关注转化和代表性留言。
7. **完成复盘**：形成表现结论、可能原因、可验证假设，并为下一篇只确定一个主要改动。

## 发布节奏

- 周三 20:30：以高共鸣的个人、婚姻或育儿观念内容为主，侧重打开和转发；
- 周日 10:00：以自我和解、亲子行动或孩子内心成长内容为主，侧重收藏、关注和长期信任；
- 提前 72 小时完成初稿，提前 24 小时完成配图和终审；
- 连续两篇不写同一种矛盾，不连续制造愤怒，育儿内容不制造家长焦虑。

完整计划见[未来 8 周选题排期](未来8周选题排期.md)。

## 写作原则

- 从生活场景或高频原话进入，先还原委屈，再解释机制，最后给出判断或行动；
- 使用具体动作、家庭语言、行为后果和可验证标准，不堆砌抽象正确话；
- 不编造作者经历、读者故事、统计数字或专家结论；
- 不替陌生人做心理诊断，不用极端个案代表所有人，不依靠群体攻击制造传播；
- 结构服从内容，不固定套用「几个原因」「几个真相」；
- 结尾提供 2—4 个可观察或可执行的行为，并留下具体、低门槛的留言问题。

详细规则见[向阳小人间文风手册](向阳小人间文风手册.md)。

## 数据复盘

每篇文章使用[运营数据看板](运营数据看板.csv)记录以下指标：

- 送达人数、阅读人数、送达阅读率和读完率；
- 分享、收藏、点赞/在看和留言；
- 新增关注、取关、净增关注和关注转化率；
- 推荐阅读、搜一搜阅读、7 天阅读和相对阅读指数；
- 关键留言、复盘结论及下一步动作。

当相对阅读指数不低于 1.3 时，应在 14 天内从不同角度延伸；同一栏目连续 3 篇低于最近 5 篇中位数时，再考虑暂停或调整。单篇波动不作为改变账号定位的依据。

## 智能学习闭环

项目内置了一个只依赖 Python 标准库的内容学习系统。它会自动扫描文章、导入运营数据、计算滚动基线、提出单变量实验，并生成周报。

```text
文章与公众号数据
      ↓
自动提取文章特征
      ↓
计算最近 5 篇动态基线
      ↓
诊断打开、读完、分享、收藏和关注转化
      ↓
提出下一篇唯一主要改动
      ↓
经过至少 3 篇验证后沉淀为长期规律
```

运行完整流程：

```bash
python -X utf8 automation/run_pipeline.py
```

输出文件：

- `data/article_features.csv`：从 `dataset/` 自动提取的标题类型、字数、段落、小标题和行动建议等特征；
- `data/article_metrics.csv`：从 `运营数据看板.csv` 导入并自动补算比例后的指标；
- `data/analysis_results.csv`：相对阅读指数、表现诊断和下一轮实验建议；
- `reports/weekly-YYYY-MM-DD.md`：自动生成的内容学习周报；
- `knowledge/`：账号基线、待验证假设、已验证规律和失败实验。

当前规则不会根据单篇数据自行修改账号定位。一个规律只有经过至少 3 篇同类文章验证、稳定高于账号动态基线，并排除热点或节假日影响后，才可以写入 `knowledge/proven_patterns.md`。

### 微信公众号 API（可选）

如果公众号已获得数据接口权限，可复制 `.env.example` 为 `.env`，填写本地密钥：

```dotenv
WECHAT_APP_ID=你的AppID
WECHAT_APP_SECRET=你的AppSecret
```

然后获取指定日期的图文和用户统计原始数据：

```bash
python -X utf8 automation/fetch_wechat_data.py --date 2026-08-26
```

接口响应保存在 `data/raw/`。再次运行完整流程时，`merge_wechat_data.py` 会按文章标题把送达、阅读、分享和收藏数据合并到指标表。`.env` 和原始 JSON 已被 Git 忽略，不会上传密钥或原始接口数据。如果账号暂时没有接口权限，继续维护 `运营数据看板.csv` 即可运行其余学习流程。

若接口返回错误码 `40164`，需在微信开发者平台的公众号“基础信息 → 开发密钥 → API IP 白名单”中添加错误信息显示的 IPv4 地址，再重新采集。动态公网 IP 发生变化后需要同步更新白名单；长期自动运行建议使用具有固定出口 IP 的服务器。

当前公众号已验证可以获取接口调用凭据，但平台没有授予图文分析和用户分析权限，相关统计接口会返回 `api unauthorized`。在权限发生变化前，项目使用微信公众号后台导出数据或 `运营数据看板.csv` 作为数据来源，后续的指标计算、诊断、实验建议和知识沉淀仍然自动完成。

### 无统计接口权限时录入数据

在公众号后台查看文章数据后，运行快照录入工具：

```bash
python -X utf8 automation/record_snapshot.py
```

程序会提示选择文章编号、T+1/T+3/T+7 检查点，并逐项录入后台数字；暂时看不到的指标可以直接回车留空。每次记录都会追加到 `data/metric_snapshots.csv`，不会覆盖旧快照。随后运行完整流程：

```bash
python -X utf8 automation/run_pipeline.py
```

系统会选择每篇文章最新的检查点，更新 `运营数据看板.csv`，自动计算各项比例并生成诊断报告。也可以使用命令参数完成非交互录入，例如：

```bash
python -X utf8 automation/record_snapshot.py --id 1 --checkpoint T+1 --送达人数 100 --阅读人数 40 --分享人数 3 --收藏人数 5
```

### 收集后台下载文件

微信后台的内容分析和用户分析下载依赖网页登录态，当前账号又没有对应统计 API，因此默认采用“浏览器点击下载、程序自动收集”的稳定方式。完成后台下载后运行：

```bash
python -X utf8 automation/collect_downloads.py
```

程序默认扫描 Windows 的 `Downloads` 目录，把最近 24 小时的 CSV、XLS、XLSX、ZIP 文件按内容哈希去重后复制到 `data/imports/`。如果浏览器下载目录不同，可在本地 `.env` 配置：

```dotenv
WECHAT_DOWNLOAD_DIR=D:\Downloads
```

也可以先预览而不复制：

```bash
python -X utf8 automation/collect_downloads.py --dry-run
```

`data/imports/` 中的微信原始导出文件已被 Git 忽略，不会上传。当前已适配微信导出的传统 XLS 内容趋势文件和 HTML 格式用户分析文件。运行 `automation/run_pipeline.py` 时会生成：

- `data/wechat_content_metrics.csv`：按文章标题和传播渠道统计的阅读数据；
- `data/wechat_daily_metrics.csv`：账号每日阅读、分享、收藏及发表篇数；
- `data/wechat_user_metrics.csv`：每日新增、取关、净增和累计关注；
- `data/article_metrics.csv`：与本项目文章标题精确匹配后的综合指标。

账号每日数据不会强行归因到某一篇文章；只有标题和发布日期都精确匹配时，文章级阅读来源才会写入运营看板。

## 封面与配图规范

- 公众号头条封面先制作 2.35:1 高清宽幅原图，再导出为精确的 900×383 PNG；
- 关键人物和主要视觉信息放在中央方形安全区，兼顾微信分享时的 1:1 缩略图裁切；
- 默认不在图片中生成标题、Logo、水印或其他文字；
- 正文配图依据最终定稿制作，不沿用与文章事件不符的旧图；
- 导出后检查尺寸、人物完整性、画面拉伸和错误文字。

## Git 与素材管理

仓库只跟踪文章、方案、规范、排期、数据模板和项目配置。以下素材通过 `.gitignore` 排除，不上传到远程仓库：

- 根目录的 `素材.txt` 及各级 `素材/` 目录；
- 整个 `image/` 目录；
- PNG、JPG、WebP、PSD 等图片文件；
- MP3、WAV、MP4、MOV 等音视频文件；
- 操作系统生成的临时文件。

日常更新建议：

```bash
git status
git add -A
git commit -m "docs: update article or operation plan"
git push origin main
```

提交前使用 `git status --ignored` 检查素材是否保持忽略状态，不要使用强制添加参数把素材写入仓库。
